# 文件分类体系 (Taxonomy)

> 一套稳定、可复用的分类维度，供 AI Agent 在项目中归置文件时参考。
> 原则：命名语义化、稳定、跨文件夹一致；不强行翻译中文文件名。
> 配合 AgentHandoff v2 协议第 2 节「目录整洁规范」使用：**新增文件必须归位，根目录只留导向文件。**

## 通用子目录模板

| 类别 | 推荐目录名 | 示例内容 | 备注 |
|:---|:---|:---|:---|
| 交接/看板 | （根目录）`handoff.md` | 项目唯一看板 | 根目录固定文件，不可移动 |
| 文档与日志 | `docs/` | 开发日志、规范、结构、决策、设计文档 | 交接体系的核心子目录 |
| 备份 | `backup/` | handoff 与日志的历史版本 | 与 archive 区别：backup 可恢复，永不删除 |
| 归档 | `archive/` | 一次性脚本、旧版、过期文件 | 用完即沉底 |
| 临时文件 | `.scratch/` | 调试脚本、草稿 | 已 gitignore，会话结束前清理 |
| 代码/模块源码 | `src/` 或 `python_codes/` | 可复用算法、接口客户端 | 交易/量化常用 `python_codes/` |
| 核心规则/系统工程 | `trading_system/`、`system/` | 规则、提示词、版本历史 | 视主题命名 |
| 策略/操作手册 | `strategy/`、`handbook/` | SOP、执行表、参考表、指标脚本 | 脚本类指标也可放此 |
| API 接入 | `api_docs/` | API 登录指南、接入文档 | |
| 复盘/记录 | `reviews/`、`reports/` | 交易复盘、分析报告 | `reviews/` 偏复盘, `reports/` 偏生成报告 |
| 测试 | `tests/` | 单元测试 | |
| 资产/素材 | `assets/` | 图、模板、非文本资源 | 不加载仅输出用 |
| 参考文档 | `references/` | 分类学、规范、外部资料 | SKILL 内部亦用此名 |
| 研究资料 | `research/`、`memecoin/` | 主题研究素材、PDF、图 | 按主题命名 |

## 归类决策规则

1. **按用途/功能分类**，不按文件类型一刀切（docx 既可属文档也可属手册，视内容）。
2. **根目录只留入口**：`handoff.md` + `README.md` + 平台薄入口文件（CLAUDE.md / AGENTS.md / .cursorrules 等）+ 规范子目录。散落单文件一律归位。
3. **新增文件登记索引**：文件放入子目录后，必须在 `handoff.md` 的「文档索引」区登记一行（文件 + 一句用途）。
4. **中文文件名保留**，不翻译；目录名可英文/拼音（跨 AI 可读性优先）。
5. **归档优先**：不确定/一次性/旧版 → `archive/`，避免污染活跃目录。
6. **稳定优先**：宁可少建目录，也别为单个文件专建目录。

## 文件名协同

- 同名不同版：加来源/序号后缀（`_v2.py`、`_codex.md`），**绝不覆盖**。
- 版本定级：内容特征（大小/元素数） > mtime；不信文件名里的 v0.x。
- 索引即入口：任何文件移动/重命名后，必须同步更新 `handoff.md` 文档索引与相关引用（grep 旧路径）。

## 反模式

| 错误 | 说明 |
|:---|:---|
| 按扩展名一刀切分目录 | .md 既可是规则也可是复盘, 按内容分类 |
| 单个文件专建一目录 | 目录>阈值原则, 避免碎片 |
| 中英混排目录名 | `python_codes`、`trading_system` 统一拼音/英文 |
| 忘记重建索引 | 文件归位后索引必须同步 |
| 在入口文件里塞项目数据 | CLAUDE.md / AGENTS.md / rules 文件只做导向，进度只写 handoff.md |
